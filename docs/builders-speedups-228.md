# Content 28 — construction drones and crystal upgrade speedups

Players start with one permanent builder slot. Purchases unlock slots 2–5 for 25, 100, 500 and 1500 gems. Each builder runs one building construction/upgrade job; connected-wall upgrades remain one batch. Local building jobs and active online infrastructure jobs share the client capacity counter. The server independently limits its infrastructure queue. Research and enhancement queues retain their existing rules. Purchases require the existing authenticated online gem service.

The header wrench opens the drone shop and displays free/total slots. Construction drones appear at work sites. Each new player-base battle spawns 1–5 repair drones from the defender's server-frozen purchased count. Wave defense uses owned slots. Repair drones fly at 1.8 cells/s, have 180 HP and repair 18 HP/s within 0.9 cells. They cannot revive destroyed buildings. Existing enemy targeting can kill them; dead drones cease repair for that battle. Purchases are permanent and drones return for the next battle. Guard snapshot slot 15 carries the builder marker through spectator updates and host transfer. They use a gold hard-hat/tool treatment on the existing drone sprite and bounded five-unit work, without new particle systems.

Online enhancement, infrastructure, research and force-tier timers expose gem speedups at ceil(remaining seconds / 30), matching existing local construction pricing. Offline crystal research also supports this rate. Existing local crystal-funded building/wall timers retain their speed buttons.

Online support transactions use the existing server gem ledger, as shield/crystal purchases do, with a durable client gem reservation and account-bound unique request id. The server computes price, checks battle locks and owner, debits once, completes the timer and saves a bound receipt atomically. A completed job costs zero. The client refunds quote minus actual cost once. Retry preserves the id; cancellation intent is saved and retried as cancellation. Cancel-before-commit records a zero-cost tombstone; cancel-after-commit returns the actual result. Pending debits are never refunded merely on network errors. Private receipts and builder ownership are keyed to auth users, independent of leaving/rejoining war enrollment.
