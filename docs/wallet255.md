# Patch 55: unclaimed NOVA, wallet transfers, raids

Existing earned and credited balances are retained. Mining and referral accrual stops automatically entering the spendable wallet. A player chooses a whole-NOVA amount; the server fixes it on an owner-bound receipt, settles earnings, checks available unclaimed balance, and transfers once after the ad completion flow. Telegram requires a secret-validated Monetag `valued` postback; Android uses the existing test-ad bridge. Neither no-fill nor an unverified Telegram SDK callback transfers currency. Verification retries keep the original receipt; after the polling window the same ad request can be retried without duplicating a transfer.

The client renders a two-decimal unclaimed estimate from server time. Prediction stops at the earliest known active-team expiry, own session expiry, or 60-second refresh boundary. The server integrates actual overlapping session intervals. A cumulative credited marker preserves existing offline-save reconciliation; this is still an in-game wallet, not a blockchain withdrawal authority.

Full destruction takes 50% of current server resources (gold, power, crystals), gives a four-hour shield, and never subtracts defender NOVA. Partial destruction uses the same resource fraction scaled by destruction. Attacker storage limits collected loot, not the defender loss. Old live/raid paths receive the same loss fraction and shield rule. Existing protection/cooldowns remain.

The server awards 40 NOVA at equal HQ level, minus 8 per level when attacking lower HQs (minimum zero), plus 4 per level when defeating higher HQs (maximum 52). Co-op siege awards are weighted by acknowledged deployments, preventing every idle room member receiving the full amount. Report INSERT completion credits once; ON CONFLICT retries do not run a new credit. Battle rewards enter the spendable wallet and are reconciled by the cumulative marker. The reward calculation still uses the existing battle host/frame validation; this patch does not introduce server-side battle replay simulation.

Below 100 distinct NOVA player/miner accounts, all levels remain eligible. At 100 or more, browsing and actual attack admission require HQ difference <=5. Shields still apply. No matchmaking threshold or future token-market text is displayed in the game.

UI: original battle-mech atlas portrait, shoulder-carried hoe, two-handed lift/strike/pull animation, soil bursts, unclaimed counter, amount entry and separate help. Existing music and walking gait retained.

Validation: complete npm suite plus wallet255 DB/UI cases covering no autocredit, partial claims, server verification, ownership, amount tampering, duplicate delivery, loss/shield, reward scaling, browsing/start gate, and report privileges. Rendered eight walking/digging poses with the actual atlas for inspection. No paid ad impressions were generated by tests.

Apply migration `nova_wallet_and_raids_255` before releasing patch 55. It does not clear wallets, mining sessions, names, referrals, or receipts. The production build reruns the suite before serving the patch.
