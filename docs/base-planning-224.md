# Base planning, patch content 24

- Drag a home building directly or use Move after selecting it. Coordinates remain a preview until the green confirmation; red cancels. Invalid and occupied cells cannot be confirmed. Empty ground continues to pan. Pointer cancellation cancels the preview. Defense ranges follow the preview.
- Compact resource header, building selection card, navigation and sheets. Building thumbnails replace several navigation symbols. Main navigation and confirmation targets remain at least 44 CSS pixels.
- New and existing accounts must claim a base name before first play on this patch. The existing authenticated native status bridge carries profile status/claim requests, so native versions 19–21 can update without an APK change.
- Names support Unicode, 1–40 code points. Display uses NFC; the unique database key uses NFKC, lowercasing, collapsed whitespace, and removes common invisible formatting characters. Control and bidi override characters are rejected; ordinary RTL text and script joiners remain supported. This is canonical-name uniqueness, not a visual-confusable filter.
- Names belong to auth user IDs in a private, RLS-enabled table. Direct client access is revoked. A checked definer command handles one-time claims, replays and uniqueness. Existing PvP command routing is preserved. A trigger synchronizes enrolled base callsigns. Leaving PvP or restoring a campaign cannot release or overwrite the account name.
- Confirmed name cache is separate from campaign saves. It permits offline return, is refreshed in the background, and is cleared on account sign-in/out. First claim requires a server response. Failed/lost responses leave the gate open with retry, and duplicate names retain the input for correction.

Validation: complete npm suite (including names224 and ui224), live database normalization/privilege/status queries, and actual Chromium rendering at mobile sizes. Pointer drag/confirm exercised in Chromium, no page errors; screenshots inspected with a Thai preview font. Database advisors only report the intended no-direct-access policy for the new private table. Physical Android device testing remains with testers.
