# Patch 80: precise air orders

Bomber commands use the clicked map coordinate, including empty ground. Existing saved games with no air manifest can deploy their available bombers. The compact bomber selector separates launching reserves from retargeting surviving aircraft, with 1 / 3 / all choices capped to actual counts. Ground troop manifests are unchanged.

Aircraft still enter from outside the map and repeat their bombing run at the selected point. A new coordinate survives host handover. Existing server order metadata (`x`, order `y`) and authenticated logistics events already carry the coordinate; no database migration is required. The server continues to reserve actual inventory and enforce ownership and nonce checks.

Duplicate order delivery no longer teleports aircraft back to entry. Helicopter/drone orders and new bomber launches do not retarget other bombers. Selecting an air type or transport highlights its command button. Landing markers identify each surviving transport; bombing markers show aircraft counts for each destination. Destroyed/returned transports are omitted from command UI and markers, while their tombstones remain in simulation for settlement.

Validation: `node tests/air280-ui.cjs` covers precise targeting, repeating sorties, old empty manifests, reserve consumption, retarget counts, highlights, dead transport removal, duplicate online orders and host handover. Existing logistics and database suites retain authority checks.
